# Интеграция 1С → сайт e'llipse: что нужно отправлять

Документ для программиста 1С. Сайт сам ничего не запрашивает у 1С — **1С отправляет HTTP POST-запросы** на сервис синхронизации (`ellipse-sync`). Ответ сервиса показывает, что принято, а что нет.

## 1. Что нужно отправлять

Для каждой пары «товар × склад/магазин» сайту нужны:

| Поле | Обязательно | Описание |
|---|---|---|
| `product_external_id` | да | GUID (Ref/УникальныйИдентификатор) номенклатуры в 1С. Тот же, что в выгрузке товаров, по которой наполнен сайт (колонка `external_id`) |
| `store_external_id` | да | GUID склада/магазина в 1С. Должен быть заранее прописан в карточке магазина на сайте (см. §6) |
| `quantity` | нет* | Остаток, целое число ≥ 0 |
| `price` | нет* | Розничная цена, > 0, до 2 знаков после запятой |
| `old_price` | нет | Цена до скидки (если есть) |
| `currency` | нет | `RUB` (по умолчанию) |

\* В строке должно быть хотя бы одно из `quantity` / `price`. Если пришёл только остаток — цены не трогаются, и наоборот.

Цена хранится **отдельно для каждого магазина**; новая запись в истории цен создаётся, только если цена изменилась.

## 2. Какие запросы нужны (набор для 1С)

| № | Запрос | Когда | Содержимое |
|---|---|---|---|
| 1 | **Остатки и цены, изменения** (`mode=delta`, по умолчанию) | каждые 5–15 минут или по событию (после проведения документов) | только строки, у которых изменился остаток или цена |
| 2 | **Остатки и цены, полная выгрузка** (`mode=full`) | раз в сутки (ночью) | все товары по всем магазинам, разбитые на пачки; нужна для «самоисцеления» и обнуления товаров, которых больше нет в наличии |

Пачки: **не более 1000–2000 строк** в одном запросе (жёсткий лимит сервиса — 2000, больше → ответ 413). Рекомендуем 500.

Новые товары/магазины отдельными запросами не передаются: товарный каталог наполняется выгрузкой товаров (отдельный процесс, см. `scripts/preprocess`). Если 1С пришлёт GUID товара, которого нет на сайте, строка не потеряется — она попадёт в список «несопоставленных», и это можно разобрать.

## 3. Формат запроса

`POST https://sync.example.com/sync/inventory-prices`

Заголовки: `Content-Type: application/json; charset=utf-8` и ключ доступа (один из способов):

- `X-Api-Key: <SYNC_API_KEY>` — рекомендуется;
- `Authorization: Bearer <SYNC_API_KEY>`;
- `Authorization: Basic base64(любой_логин:<SYNC_API_KEY>)` — если в 1С удобнее базовая аутентификация (логин игнорируется, пароль = ключ).

Ключ выдаёт администратор сайта (`SYNC_API_KEY`). Обязательно HTTPS.

### Дельта-выгрузка (пример)

```json
{
  "items": [
    {
      "product_external_id": "1c77e97a-062e-11ec-810d-ac1f6b706719",
      "store_external_id":   "a1b2c3d4-0000-4000-8000-000000000001",
      "quantity": 12,
      "price": 1249.90,
      "old_price": 1490.00,
      "currency": "RUB"
    },
    {
      "product_external_id": "4da864a2-d89a-11eb-810c-ac1f6b706719",
      "store_external_id":   "a1b2c3d4-0000-4000-8000-000000000001",
      "quantity": 0
    }
  ]
}
```

### Полная выгрузка (несколько пачек)

Все пачки одной выгрузки несут один и тот же `batch_id`, `"mode": "full"`; в **последней** пачке — `"final": true`. После неё сайт обнуляет остаток тех товаров в этих магазинах, которых в выгрузке не было.

```json
{
  "batch_id": "2026-11-18T03:00:00-full",
  "mode": "full",
  "final": false,
  "stores": ["a1b2c3d4-0000-4000-8000-000000000001", "a1b2c3d4-0000-4000-8000-000000000002"],
  "items": [ ... до 500 строк ... ]
}
```

`stores` (необязательно, но желательно в полной выгрузке) — список **всех** магазинов, которые выгрузка охватывает, включая те, где нет ни одной строки: так остатки закрытого/опустевшего магазина тоже будут обнулены. Если часть пачек не дошла и `final: true` не отправлен, обнуления не происходит — это безопасное поведение.

Если магазин один для всей пачки, его можно указать один раз: `{"store_external_id": "...", "items": [{"product_external_id": ..., "quantity": ..., "price": ...}]}`.

### Допустимые «вольности» формата

Сервис намеренно терпим, поэтому не нужно подгонять выгрузку под буквы этого документа, если стандартная обработка 1С отдаёт иное:

- имена полей можно кириллицей: `Номенклатура`, `Склад`, `Остаток`/`Количество`, `Цена`, `СтараяЦена`, `Валюта`; в любом регистре;
- числа строкой: `"1 234,50"`;
- GUID в любом регистре, в фигурных скобках, без дефисов;
- вместо `{"items": [...]}` — просто массив или массив под ключом `Товары`/`Остатки`/`data`/`rows`;
- кодировка UTF-8 (допускается и windows-1251);
- `Да/Нет`, `1/0`, `true/false` для логических полей.

Если ваш формат всё же не распознаётся, — пришлите **образец реального ответа/запроса**: это правка одного файла на нашей стороне (или файла с алиасами полей).

## 4. Ответ сервиса

HTTP 200:

```json
{
  "status": "ok",
  "batch_id": "2026-11-18T03:00:00-full",
  "received": 500,
  "updated": 498,
  "prices_inserted": 37,
  "prices_unchanged": 461,
  "zeroed": 0,
  "unmatched_products": ["…guid…"],
  "unmatched_stores": [],
  "rejected": [{"index": 17, "reason": "…", "row": {}}],
  "warnings": {}
}
```

- `status`: `ok` — всё применено; `partial` — часть строк отклонена или не найдена; `error` — ни одной строки не применено.
- `rejected` — строки, которые не удалось разобрать (причина указана); `unmatched_*` — GUID, которых нет на сайте.

Коды ошибок: **401** — неверный/отсутствует ключ; **400** — тело не JSON; **413** — слишком большая пачка/тело; **422** — формат не распознан или все строки отклонены (в ответе причина); **502/503** — внутренняя ошибка сервиса: **повторите запрос позже** (повтор безопасен: повторная отправка тех же данных ничего не ломает).

## 5. Правила и рекомендации

- **Идемпотентность:** повторная отправка пачки безопасна.
- Не отправляйте остаток `null` — отправьте `0` или опустите поле.
- Отправляйте цену именно розничную, как должна быть на сайте (с учётом скидки, если она «зашита» в цену).
- Если запрос завершился ошибкой сети/5xx — повторите через 1–5 минут, не более 5 раз, затем зафиксируйте ошибку в журнале 1С.
- Проверить, что данные доходят: `GET https://sync.example.com/sync/status` с тем же ключом — время последней успешной синхронизации и счётчики за сутки.

## 6. Что нужно от стороны 1С до запуска

Вопросы к программисту 1С:

1. **Как будет выглядеть выгрузка?** Нужен реальный образец (JSON/XML/CommerceML), пусть из тестовой базы. Есть ли уже готовый обмен с Bitrix (CommerceML), который можно использовать повторно?
2. Какое поле считать идентификатором товара — `Ссылка.УникальныйИдентификатор()`, внешний код, артикул, штрихкод? Он должен совпасть с `external_id` товаров, которыми наполнен сайт.
3. **Таблица склад ↔ магазин:** GUID каждого склада/магазина 1С и соответствующий магазин сайта (город, адрес). Заполняется через `scripts/map_store_external_ids.py`.
4. Склады какого типа считать точками продаж (оптовые/транзитные исключаем)? Нужен ли «доступный остаток» (за вычетом резерва) или «остаток на складе»?
5. Какая цена нужна — какого вида цен (розничная)? Есть ли отдельные цены по магазинам?
6. Как часто можно отправлять дельту и сколько товарных позиций в сутки меняется (для выбора размера пачки)?
7. Умеет ли 1С слать HTTPS с заголовками (`HTTPСоединение` / `HTTPЗапрос`)? Какой версии платформа? Есть ли с сервера сайта доступ к 1С — не нужен, обмен идёт только в одну сторону (1С → сайт).
8. Фиксированный ли внешний IP у сервера 1С (можно ограничить доступ к сервису по IP)?

## 7. Пример отправки на встроенном языке 1С (набросок)

Адаптируйте под вашу конфигурацию: запрос выбирает остатки и цены и отправляет пачками по 500 строк.

```bsl
Процедура ОтправитьПачку(Строки, Режим, ИдПакета, Последняя)

    Данные = Новый Структура;
    Данные.Вставить("batch_id", ИдПакета);
    Данные.Вставить("mode", Режим);          // "delta" или "full"
    Данные.Вставить("final", Последняя);
    Данные.Вставить("items", Строки);        // массив структур product_external_id / store_external_id / quantity / price

    Запись = Новый ЗаписьJSON;
    Запись.УстановитьСтроку();
    ЗаписатьJSON(Запись, Данные);
    Тело = Запись.Закрыть();

    Заголовки = Новый Соответствие;
    Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Заголовки.Вставить("X-Api-Key", КлючСинхронизации);   // SYNC_API_KEY

    Соединение = Новый HTTPСоединение("sync.example.com", 443, , , , 60, Новый ЗащищенноеСоединениеOpenSSL);
    Запрос = Новый HTTPЗапрос("/sync/inventory-prices", Заголовки);
    Запрос.УстановитьТелоИзСтроки(Тело, КодировкаТекста.UTF8, ИспользованиеByteOrderMark.НеИспользовать);

    Ответ = Соединение.ОтправитьДляОбработки(Запрос);
    Если Ответ.КодСостояния <> 200 Тогда
        ЗаписьЖурналаРегистрации("СинхронизацияСайт", УровеньЖурналаРегистрации.Ошибка, ,
            , "Код " + Ответ.КодСостояния + ": " + Ответ.ПолучитьТелоКакСтроку());
    КонецЕсли;

КонецПроцедуры
```

Пока готовой выгрузки нет, сторона сайта проверяется эмулятором: `ellipse-sync/tools/mock_1c.py` (сценарии с «неряшливыми» данными — запятые в числах, кириллица, cp1251, битые строки — и полная выгрузка по пачкам).
